# 需求：写作体验补齐（Typora 对照）

日期：2026-08-09

## 一屏摘要

- 目标：补齐日常写作高频体验、常用 Markdown 扩展语法，以及编辑器应有的小体验与文件可靠性（R1）
- 使用者：本地 Markdown 日常写作用户（笔记、文档、技术文）（R1）
- 范围：
  - 写作核心：查找替换、可关闭的字数/状态信息、脚注、YAML front matter、`[TOC]`、emoji 自动补全、飞书/钉钉等富文本粘贴转 Markdown（R2–R8）
  - 体验小缺口：关闭标签快捷键、编辑菜单全选、文档与现状对齐、编辑器内图片缩放/对齐（R9–R12）
  - 文件可靠性：外部文件变更检测、可选自动保存（R13–R14）
- 关键规则：保持单栏所见即所得与沉浸外壳；查找替换作用于当前活动文档；字数统计可关闭；扩展语法可编辑、可回写 Markdown；富文本粘贴优先转为结构化 Markdown 而非残留 HTML；不静默覆盖外部已改文件（R2–R14）
- 成功标准：上述能力均可由用户直接操作或按约定流程验证，并观察到正确结果（R2–R14）
- 不做事项：专注/打字机模式、文件夹工作区/文件树、更多导入导出格式、多窗口、设置中心大重构、云同步/图床、崩溃恢复真机验证；图片显示沿用既有实现（R15）

## 完整需求

### R1 产品目标与使用者

LightInk 定位为轻量、本地、Typora 式单栏所见即所得 Markdown 编辑器。本轮在既有内核（编辑、标签、大纲、主题、导出、图片落盘与编辑器内显示等）之上，优先补齐：

1. 日常写作高频体验与常用扩展语法；
2. 从飞书、钉钉等协作工具复制内容时的富文本粘贴转换；
3. 多标签/编辑菜单等小而高频的交互缺口；
4. 与外部编辑器同开等场景下的文件可靠性。

主要使用者是在本机用 Markdown 写笔记、文档与技术文的用户，期望少切换、少预览窗、专注内容本身，同时能顺畅承接协作工具中的内容，且不被意外丢稿或覆盖。

验收：

- 需求范围内的能力均可在单栏编辑体验中完成，不依赖双栏预览窗
- 交付说明或验收场景可独立判断是否达成，无需依赖实现细节

### R2 查找与替换

用户可在当前活动文档中查找文本，并可选择替换为其他文本。

行为要求：

- 支持在当前文档内查找匹配项，并在文档中可观察地定位到匹配位置
- 支持将匹配项替换为指定文本（至少支持逐项替换与全部替换中的一种明确策略；若两者皆提供，界面需能区分）
- 查找/替换对用户可见的文档内容生效；切换 WYSIWYG 与源码模式后，文档文本结果保持一致
- 替换产生的内容变更计入未保存状态，并可通过既有撤销路径撤销

验收：

- 给定含多处相同词的文档，用户能找到匹配项并看到当前命中位置
- 用户完成替换后，文档中对应文本已更新，且 dirty 状态正确
- 撤销后文档回到替换前内容
- 无匹配时给出可观察的空结果反馈（不静默失败）

### R3 字数与状态信息（可关闭）

用户可查看当前活动文档的写作状态信息，并可将字数统计（及相关状态展示）关闭。

至少包含：

- 字数与/或字符数（具体口径在实现前可按中文写作惯例确定，但须在界面或帮助中可理解）
- 状态信息随文档编辑更新，或在合理短延迟后更新

显示控制：

- 用户可关闭字数统计/状态展示
- 关闭后界面不再显示该信息，且偏好在下次启动后仍保持关闭
- 用户可重新打开该展示

验收：

- 编辑文档后，开启状态下可见字数/字符等信息变化
- 关闭后界面不再显示字数统计；重启应用后仍保持关闭
- 重新开启后信息恢复显示且与当前文档一致

### R4 脚注

用户可在文档中编写脚注，并在渲染态看到脚注引用与脚注内容的对应关系。

验收：

- 用户可输入符合约定的脚注语法并保存为 Markdown
- 渲染态中脚注引用与脚注正文可被识别/展示（具体交互可为跳转、底部列表或等价可见形式）
- 重新打开文档后脚注仍在，且源码与渲染一致

### R5 YAML front matter

用户可在文档开头使用 YAML front matter 记录元数据；编辑器不得破坏该块的往返保存。

验收：

- 打开含 YAML front matter 的 Markdown 时，元数据块不丢失
- 编辑正文后保存，front matter 仍保持在文档约定位置且内容不被错误吞掉
- 用户能区分/看到 front matter 的存在（源码模式可见；WYSIWYG 至少不静默删除）

### R6 `[TOC]` 目录

用户可插入 `[TOC]`（或产品明确的等价目录标记），根据文档标题生成目录。

验收：

- 文档中存在目录标记且含多级标题时，用户能看到由标题生成的目录
- 标题增删改后，目录在合理时机更新为与当前标题结构一致
- 保存的 Markdown 仍保留目录标记或产品约定的可往返表示，重新打开后目录能力仍可用

### R7 emoji 自动补全

用户在输入 emoji 触发序列（如 `:` 开头的短码）时可获得补全建议并插入 emoji。

验收：

- 输入触发序列后出现可选择的候选
- 选择候选后，文档中插入对应 emoji（或等价字符）
- 无匹配时不插入错误内容；可取消补全并继续正常输入

### R8 富文本粘贴转 Markdown（飞书 / 钉钉等）

用户从飞书、钉钉等协作/办公工具（以及浏览器、Word 等常见来源）复制富文本后，在 LightInk 中粘贴时，应将 HTML 等富文本尽量转换为结构化 Markdown 并插入，而不是整段作为无法编辑的 HTML 残留，也不是仅得到丢失结构的纯文本。

范围与优先级：

- 当剪贴板同时提供 `text/html` 与纯文本时，默认优先尝试 HTML → Markdown 结构化粘贴
- 目标来源至少覆盖：飞书文档/消息、钉钉文档/消息中常见可复制富文本；通用浏览器页面与常见办公套件作为兼容目标
- 至少应尽量保留：标题层级、段落、有序/无序列表、任务列表（若来源提供）、引用、链接、粗体/斜体/删除线、行内代码、代码块、表格、图片（能取得可落盘或可引用 URL 时）
- 无法可靠映射的样式（复杂排版、专有组件、脚本）可降级为近似 Markdown 或纯文本，不得导致粘贴失败或应用崩溃
- 既有「纯文本看起来像 Markdown」的粘贴路径（`looksLikeMarkdown` 等）继续有效；用户若只有纯文本剪贴板，行为不回退
- 粘贴结果写入文档后可保存为 Markdown，重新打开结构仍可识别
- 源码模式下粘贴：插入对应 Markdown 源文本（或等价可编辑文本），不插入原始 HTML 标签堆

边界：

- 不要求 100% 还原飞书/钉钉专有块（如多维表格、画板、投票）；能提取可读文本与基础结构即可
- 远程图片：若可获取 URL，可先以链接/图片引用插入；本轮不强制自动下载全部远程图到 `assets/`（若已有落盘路径可复用则更好，但不作为阻塞）
- 不要求「粘贴为纯文本」以外的第二种用户可选粘贴模式，但若实现提供「粘贴为纯文本」，须与默认富文本转换可区分

验收：

- 从飞书或钉钉复制含标题、列表、链接、加粗的片段，粘贴到 WYSIWYG 后可见对应结构（非一整坨无结构纯文本，亦非可见 HTML 标签）
- 保存并重新打开后，上述结构仍以 Markdown 可识别形式存在
- 从仅含纯文本 Markdown 的剪贴板粘贴时，既有 Markdown 粘贴行为仍可用
- 对无法识别的复杂 HTML，粘贴仍完成且应用不崩溃；用户至少得到可读文本

### R9 关闭标签快捷键

用户可通过键盘快捷键关闭当前活动标签（约定：Windows/Linux 为 `Ctrl+W`，macOS 为等价的 `Cmd+W`），行为与标签栏关闭一致（含未保存确认）。

验收：

- 活动标签已保存时，快捷键关闭该标签且不弹出多余确认
- 活动标签有未保存更改时，快捷键触发与点击关闭相同的未保存处理
- 快捷键可在帮助速查或菜单提示中被发现（若产品已有快捷键展示路径）

### R10 编辑菜单「全选」

编辑菜单提供「全选」，选中当前活动编辑表面的全部可编辑内容（WYSIWYG 与源码模式均可用）。

验收：

- 在 WYSIWYG 模式下执行全选后，文档内容被选中，可继续复制/剪切
- 在源码模式下执行全选后，源码全文被选中
- 无活动文档时该项禁用或无破坏性效果

### R11 文档与产品现状对齐

面向用户的说明文档（至少 `README.md`）须与当前产品行为一致，避免过时限制误导用户。

至少对齐：

- 编辑器内本地图片显示能力（已实现则不得再写为「仅导出可见」）
- 代码高亮语言覆盖描述（与当前 highlight.js 注册策略一致）
- 不再宣传已移除的性能门禁命令或固定测试用例数量

验收：

- 阅读 README 特性/已知限制后，不会与应用内可观察行为明显矛盾
- 文档中不出现已删除的 `npm run perf` / 固定「287 用例」等过时表述

### R12 编辑器内图片缩放与对齐

用户可在编辑器内调整本地图片的显示宽度（或等价缩放），并可设置常见对齐方式（至少支持左/居中/右中的合理子集，或产品明确的等价控制）。

约束：

- 调整结果须能保存回 Markdown（或产品约定的可往返表示），重新打开后显示一致
- 不引入云图床；仅作用于本地已显示的图片

验收：

- 用户改变图片显示宽度后，渲染态立即反映，保存并重开后仍保持
- 用户设置对齐后，渲染态可见对齐变化，保存并重开后仍保持
- 导出 HTML 时图片尺寸/对齐不出现明显回归（可接受与编辑器视觉近似）

### R13 外部文件变更检测

当已打开且对应磁盘路径的文件在应用外被修改时，用户应得到可观察提示，且默认不得静默用内存内容覆盖磁盘，也不得静默丢弃用户未保存编辑。

至少覆盖：

- 磁盘较新、编辑器无未保存更改：提示可重新加载
- 磁盘较新、编辑器有未保存更改：提示冲突，提供保留内存 / 重新加载（丢弃内存）等明确选择，禁止无提示覆盖

验收：

- 用外部工具修改已打开且未脏的文件后，应用出现可观察提示；用户选择重新加载后看到磁盘新内容
- 文件已脏且磁盘也被外部修改时，保存前或检测到变更时出现冲突提示，用户可做出明确选择
- 无提示的静默覆盖或静默丢编辑不作为默认行为

### R14 可选自动保存

用户可选择启用自动保存（默认关闭或产品明确的安全默认），在已有磁盘路径的文档上按时间或空闲间隔将内容写入磁盘，降低意外丢稿风险。

约束：

- 未保存过（无路径）的文档不强制静默写入用户目录；可继续依赖既有崩溃快照/草稿机制
- 自动保存不得绕过 R13 的外部变更冲突规则
- 用户可关闭自动保存；偏好跨会话保持

验收：

- 开启自动保存后，对已有路径的文档编辑一段时间，磁盘文件在无手动 Ctrl+S 的情况下被更新
- 关闭自动保存后，仅手动保存会更新磁盘
- 与外部变更冲突时仍出现 R13 要求的提示，不静默覆盖

### R15 明确不做

本轮不交付以下内容：

- 专注模式、打字机模式
- 文件夹工作区、文件树、文章列表面板
- docx / OpenOffice / LaTeX / MediaWiki / Epub 等更多导入导出格式（现有 HTML/PDF 导出保持；R8 仅覆盖剪贴板粘贴转换，不是文件导入器）
- 多窗口编辑
- 独立「设置中心」大重构（允许为字数显示、自动保存等增加轻量开关，但不以完整设置体系为交付目标）
- 云同步、图床/云上传图片
- 崩溃恢复真机（强杀进程）端到端验证：沿用既有单元测试覆盖，本轮不单独立项补真机证据
- 编辑器内本地图片显示链路本身：已有实现（`createImageSrcResolver` + `imageDisplayPlugin`），本轮只增强缩放/对齐（R12），不重做显示管线
- 独立性能门禁脚本与固定测试数量宣传
- 飞书/钉钉专有块的像素级还原与官方 API 对接

验收：

- 交付范围说明与实现清单不包含上述排除项作为本轮必达
- 本轮改动不强制引入双栏预览或云端依赖
- 既有图片粘贴/落盘/编辑器内显示与导出路径不因本轮回归
