# 需求：多格式电子书阅读（对标 Readest）与标注高亮

日期：2026-08-10

## 一屏摘要

- 目标：在 LightInk 内直接打开、阅读并标注常见电子书/文档格式，无需外部阅读器；斜杠快捷插入菜单（`/`）与阅读能力对齐（R1）
- 使用者：本地 Markdown 写作者，在写作场景中顺带阅读参考资料/电子书并做标注（R1）
- 范围：PDF / EPUB / MOBI / KF8(AZW3) / FB2 / CBZ / TXT 只读阅读标签（R2）；各格式基础阅读与导航能力（R3）；高亮/书签/笔记标注，应用内部存储（R4）；斜杠菜单新增 PDF 文件链接插入项（R5）
- 关键规则：原文件不被修改，标注不写回书籍文件；既有 Markdown 编辑、图片插入、`.md` 拖入开标签行为不回退；不引入云端/同步依赖（R2、R4、R6）
- 成功标准：每种格式样本可打开阅读并导航；标注可添加、重开后仍在、可跳转；斜杠菜单完成约定插入；Markdown 主流程无回归（R2–R6）
- 不做事项：正文编辑、格式互转、OCR、全文搜索、TTS、翻译、图书馆管理、同步、OPDS/Calibre、AI 摘要、手写批注、标注导入导出（R7）

## 完整需求

### R1 产品目标与使用者

LightInk 在既有 Markdown 编辑内核之上，扩展为可承担日常阅读场景的本地工具：用户无需离开应用即可打开并阅读常见电子书/文档格式，并对阅读内容做轻量标注。格式覆盖面对标开源阅读器 Readest（readest/readest，同为 Tauri v2 技术栈）。

主要使用者是在本机用 Markdown 写作的用户，写作过程中需要参考 PDF 文档、电子书或文本资料，并希望少切换应用、标注随文件可找回。

验收：

- 需求范围内的能力均可在应用内完成，不依赖外部阅读器
- 交付说明或验收场景可独立判断是否达成，无需依赖实现细节

### R2 多格式只读阅读标签

用户可将以下格式打开为应用内的只读阅读标签页：PDF、EPUB、MOBI、KF8(AZW3)、FB2、CBZ、TXT。

行为要求：

- 打开入口覆盖既有路径：文件菜单「打开」、OS 文件拖入窗口、最近打开列表，均接受上述扩展名
- 每种格式以独立阅读视图呈现，不进入 Markdown 编辑器
- 原文件一律不被修改：不提供编辑、不回写、不因打开产生对源文件的写操作
- 同一文件可重复打开/关闭，标签行为（关闭、切换、未保存提示等）与阅读场景的只读性质一致（只读标签无未保存确认）
- 无法解析或损坏的文件给出可观察的错误提示，不导致应用崩溃或静默无反应

验收：

- 上述每种格式各至少一个样本文件可经菜单或拖入打开为可读标签
- 打开后源文件内容与修改时间不发生变化
- 损坏/不支持的文件出现明确错误提示，应用继续可用
- 既有 `.md` 拖入开标签、图片拖入插入行为不回退

### R3 阅读基础能力与导航

阅读标签提供完成连续阅读所需的基础能力：

- 翻页或滚动阅读（具体形态可按格式与实现惯例确定，但用户可持续读完整个文档）
- 显示缩放或字号调节，调节在阅读视图内可观察生效
- EPUB / MOBI / KF8(AZW3) / FB2：提供目录（章节）导航，用户可查看章节结构并跳转
- PDF：提供页码导航（跳转指定页或等价的页定位方式）
- CBZ：按页浏览图片内容
- TXT：完整文本只读呈现，可滚动通读

验收：

- 对含多章节的 EPUB 样本，用户可见目录并跳转到指定章节
- 对多页 PDF 样本，用户可翻页并定位到指定页码
- 缩放/字号调节后显示即时变化
- CBZ 样本可逐页浏览；TXT 样本可完整滚动阅读

### R4 标注：高亮、书签、笔记

用户可在阅读标签中对内容做标注，参考 Readest 的标注能力：

- 文本高亮：对支持文本选取的格式（EPUB / MOBI / KF8(AZW3) / FB2 / TXT / 含文本层的 PDF），用户可选中文本并添加高亮
- 书签：用户可对当前阅读位置添加/移除书签
- 笔记：用户可对高亮或阅读位置附加文字笔记
- 标注列表：用户可查看当前文档的全部标注，并点击跳转到对应位置
- 持久化：标注数据保存在应用内部存储，按文件关联；应尽量以文件内容特征（如哈希）关联，降低文件移动/重命名后标注失联的概率
- 标注不写回书籍文件，源文件保持只读

验收：

- 用户选中文字添加高亮后，阅读视图中可见高亮标记
- 用户添加书签与笔记后，标注列表中可见对应条目
- 关闭并重新打开同一文件后，既有高亮/书签/笔记仍在且可跳转
- 添加标注前后，源文件内容与修改时间不发生变化

### R5 斜杠菜单新增 PDF 插入项

斜杠快捷插入菜单（`/`）新增 PDF 项：用户选择本地 PDF 文件后，在 Markdown 文档光标处插入指向该 PDF 的链接；点击该链接时，在应用内阅读器中打开对应 PDF。

约束：

- 插入的链接须能保存为 Markdown 并在重新打开后仍可用（可往返）
- PDF 文件的落盘/引用规则与现有图片资源规则保持一致（文档旁 `assets/` 或未保存文档的会话暂存目录）
- 不改动斜杠菜单现有元素集合与行为

验收：

- 斜杠菜单中可找到并触发 PDF 项，选择文件后光标处出现指向该 PDF 的链接
- 保存并重开文档后链接仍在，点击可在应用内阅读器打开该 PDF
- 既有斜杠菜单各项行为无回归

### R6 与既有能力的兼容边界

本轮改动不得破坏既有能力：

- Markdown 编辑、保存、多标签、外部变更检测等主流程不回退
- 图片粘贴/拖拽/插入菜单落盘与编辑器内显示路径不回退
- `.md` 拖入开标签、图片拖入插入的分类行为不回退，仅扩展支持新增格式
- 不引入云端服务、账号或同步依赖

验收：

- 既有前端与 Rust 测试套件通过，无因本轮改动产生的回归
- 手工验证：`.md`、图片、不支持类型的拖入行为与本轮之前一致

### R7 明确不做

本轮不交付以下内容：

- 对 PDF / EPUB / MOBI / AZW3 / FB2 / CBZ / TXT 的正文编辑与回写
- 格式互转（如 PDF/EPUB 转 Markdown）
- OCR（无文本层 PDF 的文字提取）
- 书内全文搜索
- TTS 朗读、翻译、词典/维基查询
- 图书馆管理、书库视图
- 跨设备/账号同步、OPDS/Calibre 集成
- AI 摘要、阅读统计
- 手写批注
- 标注的导入导出

验收：

- 交付范围说明与实现清单不包含上述排除项作为本轮必达
- 本轮改动不引入云端依赖或账号体系
