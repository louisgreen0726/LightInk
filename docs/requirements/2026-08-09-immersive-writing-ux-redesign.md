# 需求：沉浸写作体验与 UI 重设计

日期：2026-08-09

## 一屏摘要

- 目标：将 LightInk 重塑为默认沉浸、细节到位的本地纯写作 Markdown 编辑器（R1）
- 使用者：在本机用 Markdown 连续撰写长文与笔记草稿的人（R1）
- 范围：默认沉浸外壳、多标签默认收起、完整体验层与细节打磨；既有能力集合基本保持（R1、R2、R3、R4、R5）
- 关键规则：Typora 式单栏所见即所得不变；chrome/标签按需浮现；不改块编辑基本规则（R1、R2、R3）
- 成功标准：编辑区占主导；约定路径可唤出菜单/标签/大纲并完成常用写作与文件操作；视觉与微交互无明显割裂或粗糙感（R1–R5）
- 不做事项：笔记库/文件夹工作台、云同步协作、AI、移动端、编辑引擎大改（R6）

## 完整需求

### R1 产品目标与使用者

将 LightInk 定位为**本地、轻量、纯写作**的 Markdown 编辑器，在现有 Typora 式单栏所见即所得能力上，优先提升沉浸感与日常写作体验质感。

主要使用者是在本机连续写作的人（长文、草稿、本地笔记），其首要目标是「尽快进入正文并保持专注」，而非管理笔记库或项目文件夹。

验收：

- 产品说明与交互默认路径体现「写作优先 / 本地单机」，不引导用户进入库级组织流程
- 打开或新建文档后，用户可在无需配置的情况下直接开始正文输入

### R2 默认沉浸外壳

默认界面以编辑区为主导。顶部菜单、工具区等 chrome 默认收起或视觉上极淡，不与正文抢注意力；通过悬停、快捷键或边缘触发区可完整唤出，完成后再可收回或回到不抢注意力的状态。

验收：

- 新开空白文档或打开已有文档后，首屏中编辑区明显占主导，菜单栏不以常驻重 chrome 形态占据主要纵向空间
- 用户可通过至少一种约定路径（快捷键、悬停或边缘触发）稳定唤出完整菜单并执行「新建 / 打开 / 保存 / 导出」等文件操作
- 唤出与收回过程可预期，不出现菜单区域持续抖动、焦点丢失导致无法操作、或收回后无法再次唤出等阻塞问题

### R3 多标签默认收起

继续支持同时打开多个 Markdown 文件；标签栏默认隐藏或极淡。用户通过快捷键、触发区或其他约定路径切换活动文档、关闭标签、查看已打开列表，而无需标签栏始终常显。

验收：

- 同时打开至少两个文件后，默认布局下标签栏不常驻抢占编辑区注意力
- 用户可通过约定路径完成：切换到另一已打开文档、关闭当前或指定标签、感知当前活动文档身份（标题/路径级信息）
- 未保存关闭等既有安全提示在沉浸布局下仍可触发并完成选择

### R4 完整体验层（写作微交互）

在沉浸外壳下，对写作相关体验层做完整覆盖与打磨，包括但不限于：斜杠插入、选区格式工具条、源码模式切换与编辑、大纲侧栏唤出与跳转、空态与常用触发路径。能力集合与现有产品对齐：WYSIWYG、GFM 语法、公式与 mermaid、图片 assets、主题、HTML/PDF 导出、崩溃恢复等基本保持可用。

不改变 Typora 式块编辑的基本规则（例如光标进入块后再显示源码的总体范式）；本次不包含编辑引擎或解析规则大改。

验收：

- 在沉浸默认布局下，用户可完成：连续输入、标题/列表/代码等常用结构、斜杠插入至少一类元素、选区加粗/链接等格式操作、切换源码模式并改回、唤出大纲并跳转到标题
- 图片粘贴/插入、导出 HTML 或 PDF、主题切换等既有主路径在新外壳下仍可到达并完成
- 工具条、斜杠菜单、大纲等浮层不长期遮挡光标所在行到「无法继续输入」的程度；关闭或失焦后可恢复干净编辑区

### R5 视觉统一与细节打磨

统一内置主题下的视觉语言，并对体验细节做全量细打磨：间距与层级、焦点与悬停/激活态、空态文案与布局、过渡与反馈、状态一致性（dirty、活动标签、当前主题标记等）。深度打磨落在体验层，不扩展为产品形态变更。

验收：

- 在至少一个浅色与一个深色内置主题下，菜单、标签触发区、对话框、大纲、斜杠/格式浮层的配色与控件风格无明显「新旧两套」割裂
- 常见路径具备可预期反馈：可点击项有悬停/焦点态；危险或确认操作有明确对话框；加载或不可用状态可区分
- 不出现以下一类可稳定复现的粗糙问题：浮现布局跳动导致误点、焦点陷阱无法键盘退出、空文档无任何可理解指引且无法新建/打开、对比度低到正文与 chrome 难区分（在默认主题下）

### R6 明确不做

本次重设计明确排除以下方向，避免范围膨胀：

- 笔记库、文件夹浏览器、库级搜索/标签体系等「个人知识管理工作台」能力
- 云同步、多端实时协作、账号体系
- AI 写作助手或智能补全作为产品目标
- 移动端或 Web 托管版作为交付目标
- 将产品改为非 Markdown 主格式，或重做编辑解析引擎/块模型根本规则

验收：

- 交付范围与验收用例中不出现上述排除能力的必达项
- 交互文案与默认导航不把用户导向「建库 / 同步 / 协作」主流程
