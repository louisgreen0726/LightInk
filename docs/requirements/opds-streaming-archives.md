# OPDS 与流式归档阅读要求

本文记录 LightInk 统一书库、远程随机读取和原生归档阅读的实际能力边界。编辑器仍是默认启动界面；书库是可随时进入和关闭的独立视图，不改变 Markdown 文件、最近打开记录、进度或标注的旧数据格式。

## 功能范围

- OPDS 1.x Atom/XML 目录、子目录、`next`/`prev` 分页和 OpenSearch `{searchTerms}` 模板。
- OPDS 标题、作者、更新时间、摘要、封面和多个获取链接。
- Basic 与 Bearer 鉴权。
- 本地 PDF、EPUB、MOBI、FB2、CBZ、TXT，以及 CBR、CB7、RAR、7z。
- 远程 EPUB、CBZ、PDF 和 7z 按需读取；无 Range 资源使用完整磁盘缓存回退。
- 单卷 RAR4、RAR5 和 7z；加密归档密码只保留在当前归档会话。
- ZIP、RAR、7z 之间的多层归档，最大深度为 3。
- 固实 RAR/7z 顺序解码、进度反馈、取消和有界已解码页面缓存。
- `ComicInfo.xml` 漫画元数据、路径分段自然排序和多种漫画阅读布局。

不在本功能范围内：OPDS 2.0、OAuth、Cookie 登录、多卷归档、外部 WinRAR/7-Zip 命令，以及任意页零前置读取的固实归档。

## 使用方式

1. 通过“文件 → 书库”进入书库视图。
2. 使用“添加 OPDS 源”填写名称和 Atom/XML 目录地址；源列表中的编辑按钮可修改地址、HTTP 策略或鉴权。
3. HTTPS 源无需额外开关；HTTP 或 LAN 源必须明确启用“允许 HTTP/LAN 源”。
4. 可选择无鉴权、Basic 用户名/密码或 Bearer token。
5. 选择作品后，可挑选获取链接并“打开阅读”或“缓存整本”。
6. 本地作品可从书库导入，也可继续通过文件对话框、拖放、文件关联或 CLI 打开。

源列表、已浏览作品和获取链接写入 SQLite。删除作品只移除书库索引，不删除用户的本地原文件；“清理缓存”会清除远程正文缓存和区间索引，缓存用量旁的设置按钮可调整 LRU 上限。

## 网络安全

- 只接受 `https://` 和经用户明确允许的 `http://` URL。
- 拒绝 HTTPS 到 HTTP 的降级重定向和 Feed 链接，以及非 HTTP(S) 协议、缺少主机名、包含控制字符或内嵌用户名/密码的 URL。
- 使用 reqwest 与 rustls 执行 TLS 证书校验。
- 连接和整次请求均有有限超时，目录或资源服务器失去响应时不会无限等待。
- 单次 Range 请求最大 16 MiB；关闭书库、关闭标签或切换读取任务时，可取消打开探测、无 Range 回退下载和区间读取。
- 206 响应必须具有与请求一致的 `Content-Range`、正文长度和资源总大小。
- ETag 或 Last-Modified 变化会使旧缓存版本失效；远程阅读 identity 由作品 ID 与 validator 共同确定。两者都缺失时，缓存和 identity 仅在当前远程会话内有效，不跨会话混用未知版本。
- OPDS XML 最大 8 MiB，拒绝 `DOCTYPE`，不解析外部实体；Feed 中的摘要只作为纯文本显示。

## 凭据

- Basic 密码和 Bearer token 优先保存在系统钥匙串，服务名为 `lightink.opds`。
- 源凭据只发送到与 OPDS 根目录同源的分页、搜索和获取 URL；跨域链接不会继承该凭据。
- 系统钥匙串不可用时，凭据只保存在 Rust 进程内存中，应用退出后失效。
- 删除 OPDS 源时同步移除该源的钥匙串或会话凭据。
- SQLite 的 `opds_sources` 只保存不透明的 `credential_ref`，不保存密码或 token。
- 前端书库状态、`localStorage`、缓存文件和日志都不保存明文凭据。
- 归档密码使用独立的会话弹窗，后端以可清零字符串持有；关闭归档会话后不再保留。

## 持久化与缓存

| 数据 | 位置 | 生命周期 |
|---|---|---|
| 书库、OPDS 源、获取链接、缓存区间 | `app_data_dir/library.sqlite3` | 跨重启 |
| 远程正文稀疏文件 | `app_cache_dir/remote-cache` | LRU 或手动清理 |
| OPDS 凭据 | 系统钥匙串，失败时为进程内存 | 钥匙串或当前会话 |
| 归档密码 | 归档会话内存 | 关闭会话即失效 |

缓存默认上限为 2 GiB，可在书库界面调整（底层命令为 `library_set_cache_limit`）。缓存对象按 URL 和 ETag/Last-Modified 区分；无 validator 的对象按应用会话和远程句柄隔离。区间采用 `[start, end)` 表示，重叠或相邻区间在事务中合并。超出上限时按最近访问时间淘汰完整缓存对象，索引事务提交后再删除对应文件，且文件删除被限制在应用缓存目录内。

“缓存整本”仍以不超过 16 MiB 的区间逐段写盘。服务器拒绝 Range 时，打开资源的回退下载也直接写入缓存文件，不会先把完整响应放进 WebView 内存。

## 离线语义

- 书库索引、已浏览作品、获取链接、缓存区间和阅读进度会跨重启保留。
- 已打开会话命中缓存区间时不发送重复正文请求；网络中断后仍可读取已命中的范围。
- 目录浏览、OPDS 搜索和未缓存区间需要网络。
- 当前新建远程会话需要访问原 URL，探测大小、Range 支持并校验 validator；即使整本已缓存，完全离线启动后也不能直接跳过该校验。
- 服务器不支持 Range 时，只有完整缓存成功后才进入阅读器；缓存上限不足会在下载前或下载过程中停止。

## 格式与访问模式

| 格式 | 本地 | 远程 | 访问模式 |
|---|---|---|---|
| PDF | 是 | 是 | PDF.js Range transport；本地字节适配 |
| EPUB | 是 | 是 | ZIP 中央目录与章节资源按需读取 |
| CBZ/ZIP | 是 | 是 | 中央目录随机读取，页面按字节预算缓存 |
| RAR4/RAR5/CBR | 是 | 完整磁盘缓存后 | 非固实条目读取；固实顺序解码 |
| 7z/CB7 | 是 | 是 | Range 支持的随机读取；固实顺序解码 |
| MOBI/FB2/TXT | 是 | 否 | 保留原有本地阅读路径 |

RAR 与 7z 由纯 Rust `rars` 和 `sevenz-rust2` 解码。文件格式按魔数识别，不只依赖扩展名。不支持的压缩或加密能力返回结构化 capability error，不调用外部程序。

## 固实归档

固实归档中的多个文件共享压缩状态，无法像普通 ZIP 一样直接跳到任意条目。LightInk 的保证是：

- 原生解码，不把整个归档展开到目录。
- 按压缩块顺序解码，到目标条目后立即停止。
- 已经过的图片进入 128 MiB 后端解码缓存，前端漫画页面另受 96 MiB 页面预算约束。
- 跳到后页时显示“正在读取目标页所需的前置数据”，不伪装成随机访问。
- 新页面任务会取消旧的顺序解码；关闭标签会关闭远程与归档会话。

这不表示任意页都能避免下载前置压缩数据。目标页越靠后，可能需要读取和解码的数据越多；逆序访问也可能在缓存淘汰后重新开始。

## 嵌套归档

归档条目作为虚拟文件节点处理。只有访问到内层归档时才创建会话；外层条目写入按父 identity 与条目 ID 去重的受限缓存对象，不展开为目录树。

每一层都执行路径规范化、条目数、条目大小和压缩比检查，同时累计跨层解压预算。嵌套深度超过 3、路径穿越、超预算条目或压缩炸弹会以结构化错误停止。

## 漫画页面规则

- 优先采用 `ComicInfo.xml` 中的页序、封面、系列、卷号和阅读方向。
- 无元数据时对每个路径分段执行稳定自然排序，因此 `page2` 位于 `page10` 之前。
- 排除目录、点文件、`__MACOSX`、`Thumbs.db`、`desktop.ini`、`.DS_Store` 和常见缩略图。
- 支持 JPG、PNG、GIF、WebP、BMP 等现有浏览器可解码图片；解码失败时显示可重试错误。
- 阅读布局包括从左到右、从右到左、竖向滚动、横向分页、单双页和适合宽度。

## 安全预算

| 限制 | 默认值 |
|---|---:|
| 归档嵌套深度 | 3 |
| 单个归档条目解压大小 | 64 MiB |
| 跨层累计解压大小 | 512 MiB |
| 单层归档条目数 | 5,000 |
| 最大压缩比 | 200:1 |
| 后端固实解码缓存 | 128 MiB |
| 前端漫画页面缓存 | 96 MiB |
| 单次 HTTP Range | 16 MiB |
| 默认远程磁盘缓存 | 2 GiB |

这些预算限制内存、解码工作区和缓存增长。旧的整文件 `read_file_bytes` 限制仍用于原有本地格式；新的远程路径按区间、条目和页面预算控制资源占用。

## 兼容性

- 远程阅读标签的 `filePath` 为 `null`，不会写入本地 `recents.json`。
- 本地阅读目标继续使用原路径和原有内容哈希，因此旧进度与标注可继续读取。
- 远程进度和标注使用作品 identity 与 validator 的稳定哈希；没有 validator 时使用会话 identity，不会为计算本地 `content_hash` 而下载整本文件。
- Markdown 编辑、保存、自动保存、快照和外部文件变更检测均不处理只读阅读标签。
